# UI_base_chat.md

## Назначение документа

Этот документ фиксирует базовый UI игрового чат-окна на основе двух референсов:
- визуального референса без пояснений;
- визуального референса с пояснениями по элементам и их источникам данных.

Документ должен быть понятен:
- человеку, который проектирует или проверяет интерфейс;
- Codex, который будет воспроизводить этот экран в Django templates + Bootstrap 5 + локальном CSS + минимальном JavaScript.

Документ описывает:
- композицию экрана;
- визуальные правила;
- динамическое поведение;
- источники данных для каждого блока;
- ограничения, которые нельзя нарушать при реализации.

---

## Статус документа

Это базовая спецификация именно для **экрана чата игры**.
Она не заменяет глобальные продуктовые спецификации проекта, а уточняет визуальную и поведенческую реализацию конкретного экрана.

Если есть расхождение между этим документом и ранее утверждёнными продуктовыми правилами проекта, приоритет у ранее утверждённых продуктовых правил. При этом внешний вид должен оставаться максимально близким к этим референсам.

---

## 1. Общая идея экрана

Экран чата — это основной рабочий экран игровой сессии.

Он должен визуально восприниматься как мобильный чат-интерфейс в духе ChatGPT / Claude / мессенджера, но со своей продуктовой композицией:
- сверху фиксированная игровая шапка;
- под ней крупная кнопка завершения сценария и перехода к анализу;
- под ней закреплённый блок условий сценария;
- ниже прокручиваемая область диалога;
- внизу закреплённая зона ввода сообщения и кнопка отправки.

Ключевая идея: **верхняя и нижняя панели фиксированы, а сообщения прокручиваются между ними**.

Пользователь не переходит между отдельными страницами на каждое сообщение. Обмен сообщениями происходит динамически на текущей странице.

---

## 2. Базовая композиция экрана

### 2.1. Фон страницы

Внешний фон страницы светло-серый, близкий к референсу:
- базовый ориентир: `#e6e7e8`

На этом фоне расположен основной белый модуль чата.

### 2.2. Основной модуль чата

Основной модуль:
- белый;
- с мягкими скруглениями;
- с лёгкой тенью;
- визуально напоминает мобильную карточку/экран устройства;
- расположен по центру страницы.

На мобильном это почти вся ширина экрана с безопасными отступами по бокам.
На десктопе модуль не должен растягиваться на всю ширину. Он должен оставаться компактным и читаться как вертикальный чат-модуль.

### 2.3. Вертикальная структура

Экран состоит из 4 вертикальных зон:

1. **Верхняя фиксированная зона**
   - логотип;
   - название игры и сценария;
   - таймер.

2. **Фиксированная кнопка завершения сценария**
   - крупная оранжевая кнопка `Дай обратную связь`.

3. **Фиксированный блок условий сценария**
   - многострочный текст;
   - белый фон;
   - оранжевая рамка;
   - скругления.

4. **Прокручиваемая область диалога + нижняя фиксированная зона ввода**
   - список сообщений;
   - поле ввода;
   - кнопка `Отправить`.

## 3. Структура интерфейса

Ниже приведена логическая структура DOM/шаблона, которую нужно воспроизвести.

```text
page
  chat-shell
    chat-card
      chat-header (sticky/fixed inside card)
        header-row
          logo
          title
          timer
        finish-button
        conditions-panel
      messages-scroll-area
        message-list
          opening-message (первое сообщение ИИ)
          dialogue-messages...
          typing-indicator (при необходимости)
      chat-composer (sticky/fixed inside card)
        textarea
        send-button
```

Принципиально важно:
- `chat-header` не должен исчезать при прокрутке сообщений;
- `chat-composer` не должен исчезать при прокрутке сообщений;
- прокручиваться должна только `messages-scroll-area`;
- сообщения визуально должны уходить под верхний фрейм и подниматься из-под него при прокрутке.

## 4. Верхняя зона

### 4.1. Логотип

В левом верхнем углу располагается мини-логотип проекта.

Источник:
- статический медиа-ресурс;
- по референсу используется файл `media/UI/logo_mini.png`.

Требования:
- логотип компактный;
- не должен визуально спорить с названием игры;
- должен быть выровнен по вертикали с заголовком и таймером.

### 4.2. Название игры и сценария

В центральной части верхней строки располагается строка вида:
- `Я-Высказывание | Подчинённый`

Состав:
- слева название игры;
- разделитель `|`;
- справа название сценария / подигры.

Требования:
- строка в одну линию, если помещается;
- если не помещается, допустимо аккуратное усечение или перенос по заранее согласованным правилам реализации;
- визуально текст выполнен в фирменном оранжевом цвете.

Источник данных:
- активная игра;
- активный сценарий.

### 4.3. Таймер

В правом верхнем углу располагается таймер обратного отсчёта в формате `MM:SS`.

Примеры из референса:
- `10:00`
- `09:35`
- `06:35`

Требования:
- таймер всегда виден во время игры;
- формат строго `минуты:секунды`;
- визуально не должен доминировать над заголовком, но должен быть легко читаемым;
- цвет — тот же оранжевый или очень близкий к нему.

Источник данных:
- состояние активного диалога / игровой сессии;
- локально отображается в интерфейсе, но опирается на серверное состояние и правила таймера проекта.

## 5. Кнопка завершения сценария

Под верхней строкой располагается крупная оранжевая кнопка:
- `Дай обратную связь`

Назначение:
- завершить текущий игровой сценарий;
- запустить переход к анализу диалога по правилам проекта.

Важно:
- это не кнопка отправки сообщения;
- это отдельная игровая команда верхнего уровня.

Визуальные требования:
- крупная;
- яркая;
- по ширине почти на весь внутренний контейнер;
- крупный белый текст;
- скруглённые углы;
- должна быть визуально самой заметной кнопкой на экране.

Цвет:
- ориентир по референсу: насыщенный оранжевый`#ff5400`
- допустимо использовать один согласованный токен темы, близкий к референсу.

Источник текста:
- UI-текст из редактируемых UI-строк проекта.

Поведение:
- при нажатии запускается завершение игры по правилам проекта;
- если диалог содержит хотя бы одну пользовательскую реплику, стартует анализ;
- если пользовательских реплик нет, анализ не запускается.

---

## 6. Блок условий сценария

Под кнопкой `Дай обратную связь` располагается закреплённый блок условий сценария.

### 6.1. Назначение

Этот блок всегда показывает контекст игровой ситуации:
- кто перед пользователем;
- какая деловая рамка задана;
- в чём суть сценария;
- какие условия нужно удерживать в голове во время разговора.

### 6.2. Визуальные требования

Блок должен быть максимально близок к референсу:
- белый фон;
- оранжевая рамка;
- скруглённые углы;
- обычный чёрный/тёмно-серый текст;
- многострочный формат;
- без отдельного заголовка.

Ориентиры:
- рамка: оранжевый, близкий к цвету основной верхней кнопки;
- текст: тёмный, хорошо читаемый;
- отступы внутри блока заметные, чтобы текст не лип к рамке.

### 6.3. Поведение

Блок условий должен **вести себя как реплики чата**.

Это означает:
- при прокрутке диалога он прокручивается, как первое сообщение в диалоге;


### 6.4. Источник данных

Источник:
- поле условий активного сценария.

Рекомендуемое логическое имя:
- `conditions_text`

### 6.5. Требование к длине

Текст условий может быть многострочным.
Интерфейс обязан корректно переживать длинный текст условий без разрушения общей композиции.

---

## 7. Прокручиваемая область диалога

Это центральная область экрана, в которой отображается история переписки.

### 7.1. Общий принцип

Сообщения:
- добавляются динамически без перезагрузки страницы;
- хранятся как история диалога;
- прокручиваются вертикально;
- новые сообщения добавляются в конец;
- пользовательский интерфейс должен автоматически работать с большим количеством сообщений.

### 7.2. Порядок сообщений

Порядок элементов в начале диалога:
1. после загрузки чата пользователь сразу видит закреплённый блок условий (первое сообщение чата);
2. первым сообщением в истории идёт стартовая реплика персонажа (второе сообщение чата);
3. далее идут реплики пользователя и ИИ в хронологическом порядке.

### 7.3. Типы сообщений

Внутри области диалога должны поддерживаться минимум следующие типы элементов:
- стартовое сообщение ИИ;
- обычное сообщение ИИ;
- обычное сообщение пользователя;
- индикатор `думаю...` / временный статус ожидания ответа.

### 7.4. Динамика

Новые сообщения должны появляться без полной перезагрузки страницы.

Обязательное поведение:
- пользователь отправляет сообщение;
- оно появляется в истории;
- поле ввода временно блокируется или переводится в безопасное состояние ожидания;
- появляется индикатор, что система думает;
- после ответа ИИ индикатор исчезает, а ответ добавляется в историю;
- область сообщений автоматически остаётся возле последних сообщений.

## 8. Сообщения ИИ

### 8.1. Композиция сообщения ИИ

Сообщение ИИ состоит из двух визуальных частей:
- аватар / фотография персонажа слева;
- справа от неё текстовый пузырь.

Внутри пузыря в верхней части мелким шрифтом, оранжевым цветом отображается имя персонажа.

### 8.2. Фото / аватар персонажа

По референсу используется именно изображение персонажа.

Источник данных:
- медиа-ресурс, связанный со сценарием или персонажем сценария;
- относится к текущей игре и конкретному сценарию.

Требования:
- компактное изображение;
- с мягкими скруглениями;
- аккуратно выровнено по верхней части пузыря сообщения.

### 8.3. Имя персонажа

Имя персонажа отображается рядом с сообщением ИИ.

Источник данных:
- имя персонажа, связанное со сценарием / медиа-ресурсом сценария.

Требования:
- имя визуально небольшое;
- может быть выполнено оранжевым цветом, как на референсе;
- имя не должно спорить с основным текстом сообщения.

### 8.4. Текстовый пузырь ИИ

Визуальные требования:
- фон очень светлый, тёплый;
- ориентир по референсу: `#fff6f3`;
- округлённые углы;
- тёмный текст;
- без жёсткой рамки;
- достаточные внутренние отступы.

Выравнивание:
- сообщение ИИ находится в левой части диалога;
- аватар слева, текстовый блок справа;
- не должно выглядеть как центрированная карточка.

## 9. Сообщения пользователя

### 9.1. Композиция сообщения пользователя

Сообщение пользователя состоит из:
- текстового пузыря;
- справа от него квадратного буквенного аватара.

В верхней части пузыря справа отображается имя пользователя.

### 9.2. Имя пользователя

На референсе имя показано как небольшой текст `Username`.

Источник данных:
- отображаемое имя пользователя в интерфейсе.

В текущем проекте базовым источником должен быть **nickname пользователя**, так как он является основным пользовательским именем в продукте.

Если в конкретной реализации уже используется поле `username`, визуально это не должно менять структуру интерфейса.

### 9.3. Буквенный аватар пользователя

По референсу это квадратный синий блок с одной белой заглавной буквой.

Важное уточнение:
- референс иллюстрирует сам **визуальный тип элемента**: квадратный буквенный аватар справа;
- ранее согласованное продуктовое правило проекта требует, чтобы буква бралась из **nickname пользователя**, а цвет фона выбирался детерминированно и оставался закреплённым за пользователем.

Поэтому для реализации действует такое правило:
- форма, размер, позиция и принцип отображения — как в референсе;
- буквенный символ — первая буква nickname пользователя, upper-case;
- фон — детерминированный #004cde, спокойный, не ядовитый, достаточно светлый, чтобы белая буква всегда читалась;
- для каждого пользователя цвет одинаковый - #004cde.

Размер:
- визуально примерно квадрат 48–64 px;
- внутри одна крупная жирная белая буква.

### 9.4. Текстовый пузырь пользователя

Визуальные требования:
- холодный светлый оттенок;
- по референсу это светло-голубой/голубовато-серый пузырь;
- без жёсткой рамки;
- округлённые углы;
- тёмный текст.

Важно:
- в аннотированном референсе текстовая подпись цвета содержит противоречие с самим изображением;
- визуальная реализация должна ориентироваться на **сам видимый референс**, то есть на светлый холодный фон пузыря, а не на буквальную спорную подпись.

Выравнивание:
- сообщение пользователя находится в правой части диалога;
- текстовый блок слева от буквенного аватара;
- композиция должна быть зеркальной по отношению к сообщению ИИ.

---

## 10. Стартовое сообщение персонажа

После открытия сценария персонаж начинает диалог автоматически.

Это сообщение:
- отображается первым сообщением в истории;
- визуально выглядит как обычное сообщение ИИ;
- не требует предварительной пользовательской реплики.

Источник данных:
- отдельное редактируемое поле стартовой реплики сценария.

Рекомендуемое логическое имя:
- `opening_message_text`

Важно:
- стартовая реплика не должна быть жёстко вшита в шаблон;
- она не должна собираться из UI-текстов;
- она должна приходить из данных сценария.

---

## 11. Нижняя зона ввода

Нижняя часть экрана фиксирована внутри чат-модуля.

Она состоит из:
- многострочного поля ввода;
- кнопки `Отправить`.

### 11.1. Поле ввода

Визуальные требования:
- большой белый прямоугольник;
- синяя рамка;
- заметные внутренние отступы;
- скруглённые углы;
- текст вводится сверху слева;
- поле поддерживает несколько строк;
- при переполнении появляется внутренняя прокрутка.

Ориентир по цвету рамки:
- насыщенный синий, визуально близкий к нижней кнопке.

Поведение:
- пользователь печатает многострочный текст;
- перенос строк должен работать естественно;
- поле не должно раздувать весь экран бесконтрольно;
- при очень длинном тексте должна оставаться рабочая прокрутка внутри поля.

Источник данных:
- локальное состояние формы отправки сообщения.

### 11.2. Кнопка `Отправить`

Визуальные требования:
- широкая;
- насыщенно-синяя;
- белый текст;
- крупный размер;
- заметные скругления;
- расположена под полем ввода.

Ориентир по синему цвету:
- близкий к `#004cde` или чуть ярче;
- важно сохранить ощущение из референса.

Источник текста:
- UI-текст из редактируемых UI-строк проекта.

Поведение:
- кнопка отправляет текущее сообщение пользователя;
- должна быть недоступна, если отправка сейчас запрещена по серверной логике;
- должна защищать от многократных повторных нажатий.

---

## 12. Индикатор ожидания ответа

Во время ожидания ответа ИИ чат должен показывать промежуточное состояние `думаю...`.

Требования:
- индикатор отображается прямо в области диалога;
- не в отдельном popup и не вне чата;
- пользователь должен видеть, что обработка идёт именно как часть беседы;
- визуально индикатор должен быть стилистически встроен в ленту сообщений.

Источник состояния:
- локальное состояние клиента + результат активного серверного запроса.

| Блок условий сценария | `conditions_text` активного сценария |
| Стартовая реплика персонажа | `opening_message_text` активного сценария |
| Фото персонажа | медиа-ресурс, привязанный к сценарию / персонажу |
| Имя персонажа | данные персонажа / сценария |
| Сообщения ИИ | записи диалога, сгенерированные LLM |
| Сообщения пользователя | записи диалога пользователя |
| Имя пользователя рядом с сообщением | nickname пользователя |
| Буквенный аватар пользователя | первая буква nickname пользователя, upper-case |
| Текст кнопки `Отправить` | UI-текст |
| Содержимое textarea | локальное состояние формы |
| Индикатор `думаю...` | фронтенд-состояние активного запроса |

## 14. Поведенческие правила для динамического чата

### 14.1. Загрузка экрана

При первом открытии экрана:
1. подгружается шапка;
2. подгружаются условия сценария;
3. создаётся или подхватывается активный диалог;
4. в историю выводится стартовая реплика персонажа;
5. пользователь может сразу печатать ответ.

### 14.2. Отправка сообщения

При отправке:
1. пользовательское сообщение появляется в истории;
2. интерфейс блокирует повторную небезопасную отправку;
3. показывается индикатор ожидания;
4. отправляется запрос в backend;
5. ответ ИИ добавляется в историю;
6. интерфейс возвращается в обычный режим.

### 14.3. Автопрокрутка

После добавления нового сообщения интерфейс должен удерживать фокус на последних сообщениях, если пользователь находится в нижней части истории.

### 14.4. Ограничение по одной активной сессии

UI не должен позволять визуально породить несколько параллельных активных диалогов в рамках одного пользователя.

### 14.5. Завершение диалога

При нажатии на верхнюю кнопку завершения сценария:
- чат переводится в завершённое состояние;
- дальнейшая отправка новых сообщений запрещается;
- выполняется логика анализа по общим правилам проекта.

---

## 15. Состояния интерфейса

Экран должен поддерживать как минимум следующие состояния.

### 15.1. Initial
- шапка загружена;
- условия загружены;
- есть стартовая реплика персонажа;
- пользователь ещё ничего не отправил.

### 15.2. Active dialogue
- в истории есть как минимум одна пользовательская реплика;
- диалог идёт в обычном режиме.

### 15.3. Sending / waiting
- пользовательское сообщение уже отправлено;
- повторная отправка временно ограничена;
- в ленте виден индикатор ожидания.

### 15.4. Timer expired
- отображается системное сообщение о завершении времени;
- далее выполняется переход к анализу по общим правилам проекта.

### 15.5. Finished manually
- пользователь нажал `Дай обратную связь`;
- чат закрыт для новых сообщений;
- запускается анализ или техническое завершение без анализа, если сообщений пользователя не было.

### 15.6. Error state
- если ответ ИИ не получен или запрос завершился ошибкой, экран должен показывать аккуратную встроенную ошибку без разрушения основной композиции.

## 16. Адаптивность

### 16.1. Mobile first

Это основной сценарий.

На мобильном:
- белый чат-модуль почти во всю ширину;
- безопасные внешние отступы сохранены;
- верхняя и нижняя зоны остаются фиксированными;
- центральная зона прокручивается;
- все нажатия и поля ввода должны быть удобны пальцем.

### 16.2. Desktop

На десктопе экран не должен расползаться по ширине.

Требования:
- чат-модуль остаётся компактным;
- расположен по центру;
- вокруг может оставаться пустое серое поле;
- не должно быть ощущения «растянутой панели CRM».

Ориентир:
- на десктопе чат должен выглядеть как аккуратная крупная мобильная карточка по центру страницы.

## 17. Визуальные токены

Ниже перечислены визуальные ориентиры, которые нужно сохранить.

### 17.1. Основные цвета

- внешний фон страницы: `#e6e7e8`
- фон чат-модуля: `#ffffff`
- основной оранжевый акцент: близкий к `#ff5a00`
- основной синий акцент: близкий к `#004cde`
- пузырь ИИ: около `#fff6f3`
- пузырь пользователя: `#e6f5ff`
- основной текст: тёмный серый / почти чёрный

### 17.2. Скругления

Скругления должны быть заметными, но не мультяшными:
- карточка чата — крупные;
- кнопки — крупные;
- пузыри сообщений — средние/крупные;
- поле ввода — крупные.

### 17.3. Отступы

Отступы играют ключевую роль.
Интерфейс должен дышать:
- между верхними блоками;
- между сообщениями;
- внутри пузырей;
- вокруг поля ввода.

### 17.4. Тень

Тень у основного модуля лёгкая и мягкая. Она не должна превращать интерфейс в глянцевую карточную галерею.

## 18. Реализационные правила для Codex

### 18.1. Нельзя делать

Нельзя:
- превращать экран в SPA;
- убирать фиксированную верхнюю и нижнюю зоны;
- смешивать кнопку завершения сценария с кнопкой отправки;
- рендерить сообщения как одинаковые карточки без разделения по сторонам;
- выводить диалог с полной перезагрузкой страницы на каждое сообщение;
- заменять фото персонажа буквенным аватаром;
- делать пользовательский пузырь тёплым как у ИИ;
- делать весь экран растянутым по ширине на десктопе.

### 18.2. Нужно сделать

Нужно:
- сохранить композицию максимально близко к референсам;
- использовать Bootstrap как вспомогательную основу, а не как диктат готового шаблона;
- основную точную подгонку реализовать локальным CSS;
- чат делать динамическим;
- предусмотреть наполнение из данных модели/сервисов, а не из захардкоженных строк;
- оставить структуру удобной для будущей поддержки Android/APK-клиента на том же backend.

### 18.3. Приоритеты реализации

При конфликте между «быстро сделать» и «похоже на референс» для этого экрана приоритет у:
1. корректной композиции;
2. корректной динамики чата;
3. корректных источников данных;
4. точного визуального сходства.

## 20. Минимальный сценарий проверки готового экрана

После реализации экран должен проходить следующую ручную проверку:

1. Открывается белый чат-модуль на сером фоне.
2. Вверху видны логотип, название игры, название сценария и таймер.
3. Под ними видна крупная оранжевая кнопка `Дай обратную связь`.
4. Под кнопкой виден блок условий сценария - первое сообщение.
5. Вторым сообщением отображается стартовая реплика персонажа с фото и именем.
6. Пользователь может ввести многострочный текст в нижнее поле.
7. По кнопке `Отправить` сообщение появляется в истории без перезагрузки страницы.
8. Во время ожидания появляется индикатор `думаю...`.
9. Ответ ИИ появляется как левое сообщение с фото и тёплым пузырём.
10. Сообщение пользователя появляется как правое сообщение с буквенным аватаром и холодным пузырём.
11. Верхняя и нижняя панели остаются на месте при прокрутке.
12. На десктопе экран остаётся компактным и аккуратным, а не растягивается на всю ширину.

---

## 21. Краткая формулировка для Codex

Нужно сверстать один центральный мобильный чат-модуль на светло-сером фоне. Внутри него должны быть:
- фиксированная верхняя шапка с логотипом, названием игры/сценария и таймером;
- крупная оранжевая кнопка завершения сценария;
- блок условий сценария с оранжевой рамкой - как первое сообщение в диалоге;
- прокручиваемая лента сообщений;
- фиксированная нижняя зона ввода с многострочным textarea и синей кнопкой отправки.

Сообщения ИИ — слева, с фото персонажа и светлым тёплым пузырём.
Сообщения пользователя — справа, с буквенным аватаром и светлым холодным пузырём.

Все данные должны приходить из backend-источников сценария, игры, диалога, UI-текстов и пользовательского профиля. Никаких захардкоженных текстов в шаблоне.
